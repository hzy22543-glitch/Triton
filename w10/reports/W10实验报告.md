# W10 实验报告：Triton 按行 Softmax 的实现与正确性验证

实验日期为 2026-11-05，结果分析于 2026-11-21 补充。第 6 节的误差来自初次完整运行的 42 项检查。11 月 15 日新增 6 项 vector add 非法输入检查，回归结果为 48/48。学习讲解见 [W10 巩固学习](../docs/W10巩固学习.md)，整合过程见 [三周检查记录](../../docs/W9-W11检查与整合记录.md)。

## 1. 摘要

本实验用 PyTorch 验证 Triton vector add 和按行 Softmax。首轮 42 项全部通过。Vector add 在测过的非空输入上与 PyTorch 一致。Softmax 中，257 列比 256 列需要更多填充，但实测误差没有明显跳变。FP16 的全相等用例能逐元素匹配 PyTorch，行和却略小于 1，可以用输出舍入解释。

## 2. 目标与实现

### 2.1 Vector add

每个 program 处理 256 个位置，索引为 `program_id * 256 + arange(0, 256)`，program 数量向上取整。加载与存储均以 `offsets < n_elements` 保护边界。长度为 0 时直接返回空输出。

CUDA C++ 通常由程序员以线程索引表达每个线程的工作；这里用 Triton program 中的向量索引表达一块数据上的操作，由编译器映射到线程和 warp。`BLOCK_SIZE=256` 表示数据块元素数，不能直接解释成手写 CUDA 的 256 个线程。

### 2.2 Softmax

对第 i 行，令 m 为该行最大值，计算：

```text
y[i,j] = exp(x[i,j] - m) / sum_k exp(x[i,k] - m)
```

实数精确运算中，分子分母同乘 `exp(-m)`，因此结果不变。对有限输入，最大移位值为 0，避免直接对很大的正数求指数。浮点下仍存在舍入、近似指数和下溢，不能据此保证任意数值都精确。

每个 program 负责一行，块宽取行宽向上补齐至 2 的幂。加载无效列时填 `-inf`，使其不影响有限行最大值，且指数为 0，不增加分母；存储只写有效列。若填 0，尤其在全负数输入下，会改变归约最大值，同时无效列指数进入分母；即使最大值没有变化，也会因额外分母项产生错误。

输入加载后转 FP32，减法、指数、求和、除法在 FP32 下计算，写回时转换成输入 dtype。FP16 输入已经发生的量化损失无法由转换恢复。实现参考学习计划所列 Triton Softmax 教程的核心计算思路 [1]，未采用其 persistent 调度。

## 3. 实验要回答的问题

Vector add 主要看最后一个块没填满时能否正确读写。Softmax 主要看三件事：行宽不规则时填充会不会干扰归约，大正数输入会不会让指数溢出，以及切到 FP16 后输出和行和会偏多少。另测空输入与非法输入，核对 Python 封装是否按约定处理边界。

### 6.1 Vector add 的尾块有没有算完整？

| 向量长度 | Program 数 | 最后一个 program 的有效元素 | 最大输出绝对误差 |
|---:|---:|---:|---:|
| 255 | 1 | 255 | 0 |
| 256 | 1 | 256 | 0 |
| 257 | 2 | 1 | 0 |
| 1000 | 4 | 232 | 0 |

257 最能说明尾块的处理方式。第 2 个 program 的第一个槽位对应下标 256，其余 255 个槽位被 mask 屏蔽。这个用例和 PyTorch 逐元素一致，说明它算到了最后一个元素。1000 则覆盖了另一种尾块比例。加法的结果之所以在这些输入上能完全一致，大致是因为两边都是对同一对 FP32 元素做一次加法，每个位置互不影响，没有指数或跨元素归约带来的误差差异。

### 6.2 Softmax 补齐后，误差有明显跳变吗？

| FP32 输入形状 | 每行逻辑块宽 | 每行填充槽位 | 最大输出绝对误差 | 最大行和误差 |
|---|---:|---:|---:|---:|
| (7, 255) | 256 | 1 | 3.73e-9 | 1.19e-7 |
| (7, 256) | 256 | 0 | 7.45e-9 | 1.19e-7 |
| (7, 257) | 512 | 255 | 3.73e-9 | 1.19e-7 |
| (32, 1000) | 1024 | 24 | 2.79e-9 | 1.19e-7 |
| (16, 4096) | 4096 | 0 | 9.31e-10 | 1.19e-7 |

从 256 到 257 列，块宽翻倍，但这两组的最大输出误差仍在同一量级，最大行和误差也相同。这个现象符合填 `-inf` 的设计。补出来的槽位不抢最大值，取指数后也不占分母。4096 列的最大绝对误差更小，可能和随机长行中的单个概率通常更小有关。各组输入不同，适合看误差量级，不能用这几个数字单独判断行宽对精度的影响。

全负数用例更容易看出填充值选错会怎样。实测输入 `[-5, -4, -3, -2, -1]` 的 FP32 最大输出误差为 `5.96e-8`，行和误差也是 `5.96e-8`。用同一行补三个 0 做一个公式对照，若把 8 个位置都计入分母、最后只保留前 5 个概率，前 5 项的和约为 **0.162**。三个 0 抢了行最大值，也贡献了额外的指数项。这是按公式算出的错误填充示例。

### 6.3 大正数和极端输入为什么仍能归一化？

大正偏移用例把 `[1, 2, 3]` 和 `[1001, 1002, 1003]` 放在同一批里。减去各自最大值后，两行都变成 `[-2, -1, 0]`，所以预期概率分布相同，也避免了直接求 `exp(1003)`。该用例与 PyTorch 参考的最大输出误差在 FP32 下是 `2.98e-8`，在 FP16 下是 0。

极端用例的两行分别是 `[-10000, 0, 10000]` 和 `[10000, 10000, -10000]`。前者的概率几乎全集中到唯一的最大值，后者由两个相同的最大值均分。其余位置减最大值以后是很大的负数，指数在当前精度下趋近于 0，所以两行预期分别接近 `[0, 0, 1]` 和 `[0.5, 0.5, 0]`。两种 dtype 在这组输入上与 PyTorch 的差值均为 0，行和误差也为 0。

### 6.4 为什么对照误差为 0，行和还可能偏离 1？

FP16 全相等用例的行宽是 5，每个概率理论上为 0.2。用半精度表示时，0.2 会舍入到 `0.199951171875`，把五个存下来的值转成 FP32 再相加，得到 `0.999755859375`，距离 1 正好 `2.44140625e-4`。这个数与逐例记录的行和误差一致。Triton 和 PyTorch 都写出了相同的 FP16 值，所以逐元素对照误差为 0。两种检查分别回答了“是否与参考实现一致”和“存下来的概率加起来离 1 多远”。

最大的 FP16 输出差异出现在随机形状 `(1024, 257)`，约为 `7.63e-6`。这个差异可能来自两边近似指数、归约顺序或除法产生的细小差别，再叠加 FP16 写回时跨过舍入边界。该用例的行数也多，取全张量最大值时更容易遇到一个偏差较大的点。若想确认舍入占多少，可以对同一份 FP16 输入比较 FP32 中间结果，再比较转回 FP16 的结果。

放回测试阈值看，FP32 最大行和误差为 `2.384e-7`，约占 `1e-6` 容限的 24%。FP16 最大行和误差 `2.441e-4`，约占 `1e-3` 容限的 24%。两组绝对误差差了约三个数量级，但在各自的行和判定尺度上余量相近。FP16 随机样例 `(1024, 257)` 给出了最大逐元素差异，全相等样例却给出了最大行和偏差。一个指标看最坏位置，另一个能抓住一行上多个舍入偏差叠加的情况，保留两项更容易判断错误出在哪一层。[逐例误差](../results/runs/20261105_020646_816504/cases.json)

### 6.5 空输入和非法输入各验证了什么？

`(0, 5)` 的 FP32 和 FP16 都返回形状、类型、设备正确的空输出。它有合法行宽但没有需要启动计算的行。`(2, 0)` 和 `(2, 4097)` 则触发行宽异常。转置张量触发连续性检查，因为 kernel 用 `row_id * n_cols + col` 定位元素，无法用这个公式直接读取转置后的逻辑行。一维、CPU、FP64 用例也都触发对应的维度、设备、类型检查。

11 月 15 日的 vector add 回归还覆盖了 CPU、CPU/GPU 混用、类型、维度、形状不一致和非连续输入。典型例子是形状不一致时直接报错，避免用第一个向量的长度去读取第二个。全套 48 项通过，优化模式下单跑 vector add 也通过 14 项。 [全套回归](../results/runs/20261115_225210_984586/summary.json) · [优化模式结果](../results/runs/20261115_225215_199546/summary.json)

## 8. 结论与后续

这次最能说明实现是否正确的是三个边界用例：257 个元素的 vector add 验证尾块，257 列与全负数 Softmax 验证填充，大正偏移验证减最大值的作用。FP16 的行和偏差说明，即使与参考实现一致，写回半精度仍会影响概率的归一化程度。

本次数据适用于已测的有限值和形状。若要继续追查数值差异，可先固定同一份输入，对照 FP32 与 FP16 写回前后的结果。性能方面，W11 比较了同类 Softmax 实现与 PyTorch 基线，适合结合本报告的块宽设计一起看。 [W11 实验报告](../../w11/reports/W11实验报告.md)
