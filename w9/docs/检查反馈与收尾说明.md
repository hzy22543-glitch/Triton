## 一个容易忽略的分析陷阱

你的新 profiler 汇总表出现 `02_scale_and_mask` 的 Self CUDA 百分比超过 100%，并同时列出算子、标记范围和 kernel。不要把这些行相加，或直接据此声称某范围占总时间的 117%。本项目从原始 JSON 选择 `cat=kernel/gpu_memcpy/gpu_memset` 的实际 GPU 完整事件汇总；CPU 范围用于辅助定位，不计作额外 GPU 工作。

高有效带宽也不自动等于“超过硬件物理极限”：当前程序反复访问同一缓冲区，逻辑读写字节不等于 DRAM 实际流量。没有硬件计数器时，把缓存影响写成可能解释，不能写成已证实原因。

Compute Sanitizer 在当前环境报 WDDM debugger interface 初始化失败和 Device not supported。整数输出检查通过不消除这个限制，内存安全检查仍是未完成项。没有替用户修改系统调试设置。未来可在支持的配置下补跑，实际日志已保存。

GPU 同时承担显示任务。电源模式与是否插电未记录；结果适用于本次环境，不承诺在其他时刻有固定收益。原来那次极大波动的基准也不能证明硬件存在故障。
